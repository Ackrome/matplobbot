# Отчёт проверки OCR учебного плана

`render_curriculum_ocr_report.py` превращает уже сохранённые OCR-предсказания и
проверенный GT в автономный HTML-отчёт. Он нужен для построчной визуальной
проверки всей таблицы, сравнения моделей и просмотра кандидатов текущего
производственного парсера. Распознавание, исправление названий, публикация и
обращения к сети здесь не выполняются.

## Интерфейс

- `render_report(pdf, gt_paths, results_dir, output)` проверяет SHA-256 источника,
  загружает сценарии `predictions-*.json`, заново вычисляет метрики и записывает
  пакет отчёта. Возвращает абсолютный путь HTML, число строк, сценариев, записей
  сравнения и производственных кандидатов.
- `main(argv=None)` предоставляет CLI с обязательными `--pdf`, `--gt`,
  `--results`, `--output`. В `--gt` передаётся список файлов страниц.

```powershell
$env:PYTHONUTF8='1'
./.venv/Scripts/python.exe scripts/render_curriculum_ocr_report.py `
  --pdf C:/path/UP.pdf `
  --gt tests/fixtures/curriculum_ocr/fa_pmo_2023_page1_gt.json tests/fixtures/curriculum_ocr/fa_pmo_2023_page2_gt.json `
  --results C:/path/benchmark `
  --output C:/path/review
```

Откройте `C:/path/review/report.html` в браузере или панели Codex. Для передачи
сохраните весь каталог отчёта: HTML ссылается на локальный PDF, PNG и CSV.
Сам HTML содержит CSS и JavaScript, внешних зависимостей страницы нет.

## Файлы результата

- `report.html`: метрики, приоритетные ошибки, поиск по названиям и индексам,
  фильтры типов строк, выбор сценариев, все строки с GT и исходным сканом,
  таблица производственных кандидатов. Пустота, отсутствующий результат и
  воздержание ансамбля показаны раздельно.
- `gt.csv`: все физические строки, индекс, название, пять сырых форм контроля,
  тип, страница, ID и примечания. Кодировка UTF-8 с BOM.
- `row_comparison.csv`: одна запись на сочетание строки GT и сценария.
  Для каждого поля сохранены GT, сырое OCR и состояние: `value`, `blank`,
  `abstained`, `missing_row`, `missing_cell`. Дополнительно сохранены IoU
  сопоставления, ожидаемый тип строки, решение классификатора дисциплин и
  `classification_state`: `correct`, `mismatch`, `missing`. Отсутствующее
  решение не превращается в отрицательный класс.
- `source.pdf`: **копия оригинальных байтов**, не пересобранный PDF.
- `rows/<row_id>.png`: фрагменты оригинальных страниц по bbox GT, без deskew и
  очистки линий. Масштаб ограничен 6000 px по стороне и 24 млн пикселей страницы.
- `report-metrics.json`: метрики, пересчитанные из предсказаний на момент
  генерации, чтобы отчёт не зависел от устаревшего `metrics.json` эксперимента.
- `production-candidates.json`: неизменённая копия одноимённого входного файла,
  если он присутствует в каталоге результатов.

Если найден `dictionary-metrics.json`, отчёт показывает результаты независимого
словаря для всех сохранённых порогов. Оценки со словарём из GT явно исключены
из независимых результатов: это утечка эталонных ответов.

## Правила оценки и отображения

Используются `align_rows`, `evaluate`, `FIELDS`, `KINDS`, `control_semesters`
из `benchmark_curriculum_ocr.py`. Сопоставление строк однозначное, по странице
и вертикальному IoU, без текста и индексов. Предсказания уже существуют до
загрузки GT; GT используется только для оценки, порядка проверки и
иллюстративных фрагментов. Выбор OCR-ячеек этим скриптом не производится.

Факты относятся к строкам дисциплин; значения разделов и итогов оцениваются
как текст, не наследуются дочерними строками. Приоритет проблем определяется
базовым сценарием, начиная с потерянных/лишних фактов, затем ошибками типа
строки, индексами, названиями и ячейками. Ошибка классификации выделяется и
попадает в фильтр проблем, даже когда все формы контроля пусты. В сводке
выведены TP/FP/FN/TN классификатора строк и число отсутствующих решений;
положительный класс — дисциплина. Заведомо неудачный сценарий без deskew не вытесняет
реальные проблемы базового парсера. При отсутствии `baseline` явно используется
первый сохранённый сценарий.

По умолчанию видны базовый сценарий, сценарий с наибольшим F1 фактов, ONNX,
лучший ансамбль и `best_clean6`, если они доступны. Остальные можно включить.
Максимальный F1 на одном плане не означает готовность к производственному
использованию. Время ансамбля обозначено как сумма участников, а не отдельный
независимый замер; попадания в кэш показываются рядом.

Сценарий `hybrid_fields_development` и результаты с флагом
`development_hypothesis` имеют видимую метку Development в сводке, выборе
моделей и построчной таблице. Отдельное пояснение сообщает, что источники полей
выбраны по результатам на этом же GT, а независимого held-out-набора нет.
Высокие показатели такого сценария не представлены как независимая проверка.

В таблице красным отмечаются также буквальные отличия при совпавших номерах
семестров — такой случай сопровождается пояснением. Название и индекс не
исправляются. HTML-значения экранируются, ID строк проверяются перед созданием
путей. CSV сохраняет исходный текст; импортировать его в электронную таблицу
нужно как текст, чтобы не изменить индексы, запятые и начальные символы.

## Зависимости, побочные эффекты и сопровождение

Нужны проектная `.venv`, `pypdfium2`/Pillow, модуль бенчмарка и штатный парсер
семестров/индексов. Tesseract, ONNX-модели и GPU для рендера не нужны. Входные
файлы читаются без изменения. Запись идёт только в `--output`; существующие
одноимённые артефакты перезаписываются. Не указывайте каталог с нужными
пользовательскими артефактами в качестве вывода.

После изменений проверяйте количество строк и CSV, совпадение хеша копии PDF,
поиск/фильтры, различение `blank`/`abstained`, узкий экран и отсутствие
горизонтального переполнения всей страницы. Прокрутка широких таблиц должна
оставаться внутри их контейнеров. Сохраняйте семантику метрик синхронной с
`benchmark_curriculum_ocr.py`; не фиксируйте в коде число строк, моделей и
текущие показатели качества.
