# lesson_details.js

Карточка занятия в нативном модальном `dialog` с вкладками «Занятие» и «Дисциплина».
Показывает сведения из расписания. Вкладка «Дисциплина» при первом открытии читает
весь серверный кэш выбранной сущности через `ScheduleApi.loadCachedScheduleData`;
не создаёт описаний курса, которых нет в источнике.

## Публичные функции

- `MpbLessonDetails.open(raw, context, trigger)` открывает карточку исходной записи.
  `context` содержит `schedule`, `entity`, `bounds`, `sourceUpdatedAt`, `freshness`,
  `offline`, `refreshing`, необязательный `prepareLesson` (нормализация модулей);
  `entity.id` — разрешённый сервером ID из `/schedule/data`.
  `trigger` получает фокус при закрытии.
- `normalizeLesson(raw, entity)` выбирает полное название и имя преподавателя,
  отделяет числовые идентификаторы, проверяет дату/время, собирает необязательные
  корпус, почту, подгруппу, примечание и безопасные HTTP(S)-ссылки.
- `relatedLessons(selected, schedule, entity, includeSelected = true)` возвращает хронологические записи
  дисциплины. Если оба ID дисциплины присутствуют, сравнивает их; иначе сравнивает
  нормализованное полное название и модуль. Убирает дубли видимых сведений,
  сохраняя разные аудитории, преподавателей, группы и подгруппы.
  Для полного кэша передаётся `false`, чтобы не возвращать удалённые занятия
  из старой выборки. Пустой серверный снимок остаётся пустым.

## Пример

```js
MpbLessonDetails.open(lesson, {
    schedule: fullSchedule,
    entity: { type: 'group', id: '7', name: 'ПМ23-1' },
    bounds: { start: '2026-10-01', end: '2026-10-31' },
    sourceUpdatedAt: '2026-10-09T09:00:00Z',
    freshness: 'fresh_cache',
}, clickedButton);
```

Обычная точка входа — `showLessonDetails` в `schedule.js`: она передаёт текущее
состояние, включая записи за пределами видимой недели и выбранных модулей.
Эти локальные записи служат запасным списком на время загрузки или ошибки.

## Зависимости и побочные эффекты

`schedule_api.js` читает `/schedule/cache/{type}/{id}` с `cache: no-store`.
Один запрос на открытое окно, без обновления upstream; повторение после ошибки
явное, новое открытие читает актуальный снимок заново.
`frontend_i18n.js` и ключи `schedule.details.*` в RU/EN; `lesson_details.css` и
тематические переменные страницы. `ScheduleRender.downloadSingleLessonIcs`
скачивает одно занятие с полным названием и московским временем.
`openLessonEntitySchedule` обрабатывает явные переходы к другим расписаниям.
Clipboard API используется только по кнопке; при отказе появляется выделенный текст.

На время открытия создаётся один dialog, блокируется прокрутка страницы; нативная
модальность исключает фон из взаимодействия. Tab удерживается внутри, Escape и
нажатие на backdrop закрывают окно. После закрытия восстанавливаются overflow,
фокус и прокрутка страницы/таблицы; обработчик смены языка удаляется и
незавершённый запрос отменяется. Тайм-аут 12 секунд показывает ошибку с повтором.
Асинхронный ответ заменяет только содержимое вкладки дисциплины, не переключает
активную вкладку и не меняет фокус вне обновляемого блока.

## Сопровождение

Даты расписания трактуются в Москве, не в часовом поясе браузера. Некорректные
интервалы не экспортируются. Не показывать lecturer как имя, если это ID.
Все исходные строки выводятся через textContent; ссылки не допускают javascript,
data и встроенные логин/пароль. Время проверки не означает время изменения пары.
Счётчики относятся ко всему доступному кэшу текущей сущности, обычно семестровому.
Даты берутся из фактических занятий, а время проверки — из того же снимка.
Не обещать полноту семестра: университет мог ещё не опубликовать будущие пары.
При недоступном кэше явно обозначать неполный локальный список.
Проверять клавиатуру, восстановление прокрутки, RU/EN, обе темы и 320–1920 px.
Модель покрыта `tests/test_lesson_details.py`; реальные DOM-сценарии проверять
браузером. При изменении ассетов синхронизировать URL страницы и precache.
