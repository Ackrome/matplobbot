# curriculum_worker.py

Private subprocess entry point used by `curriculum_processing.py`. `parse_document(bytes, scan_layout=None)` first uses the existing pdfplumber table parser, then invokes `curriculum_ocr.parse_scanned_curriculum(..., layout_profile=scan_layout)` only for pages with a raster scan, including scans containing a small text watermark. Mixed documents retain native records on non-scanned pages; scan pages belong exclusively to the scan parser, preventing duplicate native-overlay and synthetic-row identities.

Usage is internal: `python -m shared_lib.services.curriculum_worker source.pdf result.json --scan-layout fa_legacy_v1`. Omit the optional layout to allow known-source selection. argparse limits the setting to declared profiles. Both paths are generated by the parent in a private temporary directory. The child never opens a database or downloads a document. Runtime imports are lazy, so text-only work does not load OpenCV or ONNX Runtime. Scans require scheduler-only CPU OpenCV, PDFium, ONNX Runtime and Tesseract rus+eng; Tesseract reads discipline names while the packaged numeric model reads control cells.

The Linux entry point applies address-space, CPU-time and file-size resource limits before importing heavy libraries. The parent separately enforces wall time and kills the process tree. PDF inputs retain the shared 20 MiB/100-page bounds and results retain the 5000-record/8 MiB limits. Any OCR attempt marks the combined document `needs_review`; a parse result is never automatic publication.

Maintain mixed-page dispatch and deduplication tests when changing image detection. Do not infer a semester or an assessment from OCR word order. Increase the parser version in `curriculum_processing.py` when changing extraction behavior. Windows is supported for local testing but does not offer Linux resource limits.
